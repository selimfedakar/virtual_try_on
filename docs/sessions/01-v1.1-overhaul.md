# Session 01 — v1.1 Full Overhaul (2026-07-07)

**Scope:** execute the complete update plan (`vto-guncelleme-plani-2026-07-04.md`) end to
end — Tier A (compliance & honesty), Tier B (mid-term product), Tier C (long-term vision)
— in one session, orchestrated across four parallel work streams (backend, web,
mobile-core, mobile-features) plus an integration pass.

**Result:** all plan items implemented. Mobile `tsc` clean, root `tsc` clean,
`next build` green (13 routes), `expo-doctor` clean except one known-benign monorepo
warning. Nothing committed — atomic commit plan handed to Selim separately.

---

## 1. Why

VTO v1.0 shipped with review-risk debt (a false camera-permission claim, a fake
"AI Stylist", a decorative content-report button), an active revenue leak
(client-written `is_premium`, no server verification), zero observability, and several
backend security gaps (open scraper, fail-open webhook). v1.1 turns every fake surface
into a real feature and closes every identified hole, so the next App Store submission is
both safer and genuinely better.

## 2. What was built

### Platform upgrade
- **Expo SDK 54 → 55** (React Native 0.81.5 → 0.83.6, React 19.2), all `expo-*` packages
  aligned via `expo install --fix`. Removed SDK-55-defunct config (`newArchEnabled`,
  `android.edgeToEdgeEnabled` — both are always-on now; expo-doctor schema check verified).
- New deps: `@sentry/react-native`, `expo-notifications`, `react-native-view-shot`.
- `eas.json`: `ios.image: latest` so EAS builds with a current Xcode (lesson from
  EXCAR's ITMS-90725 rejection).
- Deprecated API sweep: `ImagePicker.MediaTypeOptions` → `['images']` everywhere;
  `expo-file-system/legacy` → modern `File`/`Directory`/`Paths` API.

### A — Compliance & honesty (App Store risk → zero)
- **A1** `NSCameraUsageDescription` no longer claims "your photo never leaves your
  device" (it goes to the backend and Fashn.ai). All permission strings rewritten
  honestly, aligned with the AI consent modal. `PrivacyInfo.xcprivacy`
  `NSPrivacyCollectedDataTypes` filled (Photos/Videos, Email, UserID, PurchaseHistory
  linked; CrashData, PerformanceData not linked) and mirrored in `app.json`
  `ios.privacyManifests` for prebuild.
- **A2** The Style tab is now a **real AI stylist**: `POST /api/stylist` calls Claude
  (vision, structured JSON output) to analyze the garment photo and return a garment
  analysis + 3 personalized suggestions. 10 requests/day free, premium unlimited
  (`check_and_increment_stylist` SQL function). Mobile tab fully rewritten — the three
  hardcoded `OUTFIT_SETS` cards are gone.
- **A3** Content report is real: `POST /api/report` → `reports` table (service-role
  only, 10/day rate limit); mobile flow asks a reason and submits with auth.
- **A4** Fake AR theater removed: "✓ FIT DETECTED" badge and scan-line animation
  deleted; "LIVE PREVIEW" renamed "AI PREVIEW".
- **Android** manifest cleanup (C4 prep): dropped `RECORD_AUDIO`, `READ_MEDIA_VIDEO`,
  `READ_MEDIA_AUDIO`.

### A — Infrastructure
- **A5** Observability: Sentry (compile-time no-op unless `EXPO_PUBLIC_SENTRY_DSN` set)
  + first-party analytics (`track()` → Supabase `events` table, insert-only RLS).
  Instrumented: `generate_started/succeeded/failed`, `paywall_shown/purchased`,
  `stylist_used`, `report_submitted`, `url_import_used`, `look_shared`,
  `outfit_created`, `daily_reminder_toggled`.
- **A6** Revenue leak closed: new `POST /api/webhook/revenuecat` (fail-closed auth)
  owns `profiles.is_premium` — set true on INITIAL_PURCHASE/RENEWAL/UNCANCELLATION/
  PRODUCT_CHANGE, false on EXPIRATION (CANCELLATION deliberately keeps access until
  expiry). All client-side `is_premium` writes removed from `PaywallModal`.
- **A7** Backend hardening: `/api/scrape` now requires Bearer auth + SSRF protection
  (https-only, private/loopback/link-local/metadata IP rejection incl. DNS resolution
  and redirect re-validation, 5 s timeout, 2 MB cap); Fashn webhook **fail-closed** on
  missing/mismatched secret; `ADMIN_EMAILS` moved to env; **quota refund**
  (`refund_generation` RPC) when the Fashn call fails or the webhook reports a failed
  generation (atomic claim prevents double refunds) — a failed generation no longer
  burns one of the user's 5 daily credits.
- **Race fix:** generations now store `prediction_id`/`storage_path`/`category`; the
  polling fallback looks results up by `prediction_id`, never "latest row in 15 min"
  (which could return another concurrent generation's image).
- **A8** Repo hygiene: stray root `app.json` (wrong bundle id — the same class of file
  that broke EAS project-root detection before) deleted; mockup tooling ignored;
  `.env.example` documents every variable; README rewritten (Fashn.ai/Next 16/SDK 55
  reality); this journal started.

### B — Product
- **B1** Garment category (Top / Bottom / Full Body) — mandatory explicit choice in the
  try-on flow, passed to Fashn.ai `category` (fixes the "pants render broken" issue;
  re-introduced deliberately after the 438fb43→0661af5 revert, this time with no default
  so users can't skip it accidentally).
- **B2** Monetization: PaywallModal renders all RevenueCat packages dynamically
  (monthly + annual with computed savings %, intro-offer display); Profile has a
  Subscription section (status, Manage subscription → App Store, Upgrade → paywall).
- **B3** Fit Analysis 2.0: fake 900 ms spinner removed; optional chest/waist/hips
  measurements; garment-type-aware size recommendation against an embedded S–XXL chart
  with an honest "varies by brand" disclaimer.
- **B4** Onboarding: first-launch 3-slide pager + bundled demo garment
  (`assets/demo-garment.jpg`, cropped from an existing mockup) with a one-time
  "Try a sample garment" chip on Home.
- **B6** Share watermark: offscreen branded card (try-on image + "VTO · Virtual
  Try-On" badge) captured via `react-native-view-shot` and shared as an image file;
  falls back to the plain URL if capture fails.
- **B7** Hygiene: daily Vercel cron (`/api/cron/cleanup`, `CRON_SECRET`-protected)
  sweeps `pending_generations` older than 2 h.
- **B8** Web decision executed: the broken web try-on (401-by-design) is retired; the
  site is now a dark, honest marketing landing + `/support` FAQ + `/terms`, matching
  the app's palette. Dead components, `mediapipe`, `replicate`, `lucide-react` removed.

### C — Vision features (pulled forward into this release)
- **C1** Try-on from URL: paste a product link → authed scraper → garment image
  imported into the flow.
- **C2** Closet 2.0: long-press categorization, category filter chips, outfit builder
  (top + bottom pairs, stored locally per user), daily 9 AM "what to wear" local
  notification (opt-in toggle).
- **C3** Quality mode: `mode: 'quality'` premium-gated **server-side** (silently
  downgraded to `balanced` for free users) with a Standard/High-Quality toggle in the app.
- **C5** Community: post looks (`shared_looks`), like via `toggle_look_like` RPC
  (optimistic UI + server reconcile), view counts, weekly `style_challenges` banner with
  seeded first challenge.
- Guest/user isolation (§3.12): all local persistence (photos, garments, outfits) is
  now keyed per Supabase user id via `userScope.ts`, with one-time migration of legacy
  global keys.

### Database
Everything ships in **`supabase_v1_1.sql`** (idempotent, commented): generations
columns + indexes, `refund_generation`, `reports`, `stylist_usage` +
`check_and_increment_stylist`, `shared_looks`/`look_likes` + RPCs, `style_challenges`
(+ seed), `events`, RLS on all of it.

## 3. Decision log (with rejected alternatives)

| Decision | Rejected alternative | Why |
|---|---|---|
| SDK 55 (not 56/57) | Jump straight to latest SDK 57 | One-major-version upgrades are the supported path; 55 was the plan's target and RN 0.83 already forces the Xcode/EAS image bump. Fewer variables before a store submission. |
| First-party analytics (Supabase `events`) | Amplitude/PostHog SDK | Zero new vendor, zero SDK weight, RLS-safe, queryable with SQL next to product data. Funnel needs are simple (a dozen events). |
| Claude Haiku via raw `fetch` for the stylist | Anthropic SDK dependency; GPT-4o | No new npm dep on Vercel; Haiku is fast/cheap for one-image analysis (~$0.002–0.005/request); structured-output enforces the JSON contract. |
| RevenueCat webhook owns `is_premium`; CANCELLATION ≠ revoke | Revoke on CANCELLATION | Apple subscriptions run until period end; revoking early would rob paid time and generate support tickets. EXPIRATION is the correct revoke signal. |
| Quality-mode downgrade is silent server-side | 402/403 error for non-premium `quality` | The client already gates the toggle; a server error would break UX on entitlement propagation lag. Server enforcement still prevents abuse. |
| Category has **no default** in the UI (backend defaults `tops` only for old clients) | Preselect `tops` | The 438fb43 attempt failed partly because users skipped the selector; explicit choice is the only way the model gets correct params. Backend default keeps v1.0 clients working. |
| Watermark via offscreen ViewShot card | Server-side compositing; `expo-image-manipulator` overlay | Manipulator can't composite text; server-side costs bandwidth+latency. ViewShot is local, instant, and falls back gracefully. |
| Web try-on retired, site = landing/support | Fix web generate with Bearer auth | The app is the product; a second full auth surface doubles review/maintenance for ~zero users. Support URL now actually supports. |
| Local daily notification | Push server | "What to wear" needs no server state; local scheduling ships in one file with no infra. |
| `pending_generations` TTL via Vercel cron | Supabase `pg_cron` | Keeps ops in one dashboard (Vercel) and the secret in env; pg_cron availability varies by plan. |

## 4. Bugs & gotchas hit this session

1. **`@sentry/react-native/expo` config plugin crashes `expo config`** when
   `@expo/config-plugins` isn't a top-level dep. Root cause: the plugin resolves the
   package from the project root. Deliberately shipped **without** the plugin (runtime
   SDK works; only source-map upload needs it) — re-add after
   `npx expo install @expo/config-plugins` (ops step).
2. **SDK 55 schema drift:** `newArchEnabled` and `android.edgeToEdgeEnabled` are no
   longer valid app.json keys (both always-on). Found by `expo-doctor`, removed.
3. **expo-doctor duplicate-react warning** (`19.2.0` mobile vs `19.2.3` root): benign —
   the mobile app has its own `node_modules` and lockfile and EAS builds from
   `ai-vto-mobile/`; the root React belongs to Next.js. Known monorepo-layout artifact.
4. One work stream was interrupted externally mid-flight (share.tsx in progress);
   recovery = state diff against its task list showed only `history.tsx` (Closet 2.0 UI)
   and `profile.tsx` (subscription section) missing — completed in the integration pass
   without redoing finished work.
